# Contributor Evaluation Policy

This is the canonical policy for how AnchorKit contributors are evaluated after
submitting a pull request. It applies to all contributions, including GrantFox
OSS / Maybe Rewarded issues.

The policy is intentionally brief. Each rule links to the existing guide that
defines the standard in detail.

## Evaluation After Merge

Merge approval is a prerequisite for reward consideration but does not itself
guarantee reward-readiness. GrantFox campaign evaluation happens **after merge**
and is separate from code review.

See [GrantFox Contribution Workflow §8](./GRANTFOX_WORKFLOW.md#8-merge-and-reward-readiness)
and [Contributor Payment Expectations](./CONTRIBUTOR_PAYMENT_EXPECTATIONS.md).

## What Evaluation Depends On

Campaign reviewers assess a merged PR against these factors. Each is documented
in full in the linked guide.

| Issue acceptance criteria | [Acceptance Criteria Completion](./ACCEPTANCE_CRITERIA_COMPLETION.md) · [Issue Approval Readiness](./ISSUE_APPROVAL_READINESS.md) |
| Testing evidence | [Test Evidence PR Requirement](./TEST_EVIDENCE_REQUIREMENT.md) · [Minimum Testing Standard](./MINIMUM_TESTING_STANDARD.md) |
| CI status | [Failing CI Response Guide](./FAILING_CI_RESPONSE_GUIDE.md) |

## Contributor Self-Review

Before requesting review or following up about payment, complete a self-review
against the issue scope, acceptance criteria, tests, CI, and documentation.
See [Contributor Self-Review Template](./CONTRIBUTOR_SELF_REVIEW_TEMPLATE.md)
and [Evaluation-Readiness Dashboard](./EVALUATION_READINESS.md).

## Maintainer Review Standards

Maintainers evaluate every PR against the project's quality, security, and
documentation checklists. Contributors should read these before opening a PR.
See [Maintainer Review Checklist](./MAINTAINER_REVIEW_CHECKLIST.md),
[Reviewer Quality Checklist](./REVIEWER_QUALITY_CHECKLIST.md), and
[Reviewer Evidence Checklist](./REVIEWER_EVIDENCE_CHECKLIST.md).

## Payment-Period Conduct

Do not post repeated payment follow-ups across unrelated issues, pull requests,
discussions, or maintainer channels. Ask once with evidence, then wait for the
documented evaluation process.
See [Payment-Period Communication Policy](./PAYMENT_PERIOD_COMMUNICATION_POLICY.md)
and [Payment-Period Conduct Note](./PAYMENT_PERIOD_CONDUCT.md).
